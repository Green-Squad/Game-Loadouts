# Hand-Forged Edition

The original Laravel 4.1/PHP 5.6 application from master, including original public/admin layouts, controllers, forms, CSV import and uploads. `HAND_FORGED_DEMO=true` enables only the demo notice and isolation adapters: local mail captured in the visitor's file session, a local guest-verification checkbox, local search in the existing results view, and disabled ads/analytics/Disqus. Cookie names and a randomly generated application secret are independent. Sample confirmation/reset links use this demo host.

- Administrator: `admin@handforged.invalid` / `HandForgedDemo!`
- Visitor: `demo@handforged.invalid` / `HandForgedDemo!`

`catalog.json.gz` contains a clean snapshot of all 11 public games, 843 weapons, 5,855 attachments and 28,269 compatibility relationships captured 2026-10-12. No real users, credentials, submissions or votes are copied. `seed.sql.gz` uses the original schema with synthetic users, combinations and votes. See the provenance manifest. The original sitemap 2.4.12 source is pinned to its publisher archive because the historical release was removed from current Packagist listings; the demo dependency lock keeps Laravel 4.1.31 and CSV 8.2.3. Original fonts are bundled locally. MySQL 5.7.44 is pinned for historical compatibility. Its image preinitializes a clean database snapshot at build time; startup copies that small snapshot to an ephemeral memory volume, rebases synthetic dates, then opens the private database port. Web startup verifies populated seed counts before opening HTTP.

Only the web container is public. MySQL has no published service port and no production/VPS connection. No persistent database, disk or uploads volume is created. Writable application files and uploaded artwork live in the instance's ephemeral filesystem. Replacing the server restores the image's artwork and seed. Visitors sharing an instance share database edits; closing a browser does not reset them. Deployments can briefly overlap separate instances. Captured email is limited to its browser's demo session.

The separate hand-forged Cloud Build trigger must match `^hand-forged$` and use `hand-forged/cloudbuild.yaml`. That config checks the branch and fixed service name `gameloadouts-hand-forged`, project `game-loadouts`, region `europe-west1`; it cannot select the original or Rust services through substitutions. Image packages reuse the existing regional registry. The second-generation Cloud Run service uses request-based billing, min zero/max one, bounded resources and a database-before-web startup dependency. Its dedicated runtime identity has no project roles. The workflow waits for the matching isolated CI check before deploying and enables public invocation only for this demo service. The domain mapping is one-time setup.

`bash hand-forged/check-container.sh` uses CI-built demo images to check original public/admin forms, uploads, create/update/delete, attachment relationships, CSV import, submissions/votes, captured mail/search and isolated cookies. Chromium checks rendered desktop/mobile interactions. Replacing both containers must lose modifications and uploaded markers, restore all seed users, and leave MySQL unpublished. Measurements and screenshots are saved as CI artifacts.

These are intentionally historical runtimes; no framework modernization is included. Snapshot/date initialization happens before requests. The original controller limitations remain where they do not prevent these demonstrated flows. Artifact Registry storage, build minutes, active/startup compute and traffic can incur costs despite scale-to-zero; free allowances are shared with the account. Do not promise guaranteed zero cost. Keep only demo image versions needed for rollback rather than changing cleanup of production packages.
